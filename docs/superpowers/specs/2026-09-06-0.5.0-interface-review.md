# 0.5.0 interface review: `series.Series` and `dataframe.DataFrame`

Date: 2026-09-06 · Scope: the two public interfaces (`series/series.go`,
`dataframe/dataframe.go`), reviewed for the 0.5.0 "stabilize for 1.0" window —
the one release where breaking changes are batched. Everything here is a
proposal; items marked **decide** need a judgment call, items marked **do**
are mechanical and safe to batch.

## The headline question: does `DataFrame` need to be an interface?

`DataFrame` has exactly one implementation, `BaseDataFrame`, and the interface
is already sealed by accident: `getPartitions()` is unexported and
`Agg(...) aggregatorBuilder` names an unexported type, so no external package
can implement it. What the interface buys today is indirection, a second place
to keep doc comments in sync, and the awkward unexported-wrapper return types.
What it costs: every new method is a "breaking change" to a contract nobody
else implements, and pkg.go.dev shows a split surface.

Options, in order of preference:

1. **Collapse to a concrete type** — rename `BaseDataFrame` to `DataFrame`
   (struct), drop the interface. Interfaces with one implementation are a Go
   anti-pattern; a future lazy or remote frame can introduce its own seam when
   it actually exists (0.4.0 made `GroupBy` lazy *inside* the one type, which
   is evidence the seam is not needed for that).
2. Keep the interface but seal it *deliberately*: a doc comment stating it is
   not for external implementation, and keep one unexported method as the
   seal.

`Series` is the opposite case: nine concrete types implement it and the
per-type codegen is the design. The interface earns its keep — keep it.

**decide** (1 vs 2). Everything below applies either way.

## Cross-cutting idioms (both interfaces) — **do**

- **Errors**: `IsError() bool` + `GetError() string` (Series) and
  `IsErrored() bool` + `GetError() error` (DataFrame) become the standard Go
  `Err() error` (nil when healthy). The in-band `Errors` series stays — it is
  how errors flow through dynamic pipelines — but it should carry and expose a
  real `error`, so callers can wrap, compare and `errors.Is` it.
- **Drop the `Get` prefix**: `GetContext`→`Context`, `GetPartition`→
  `Partition`, `GetNullMask`→`NullMask`, `GetSeriesIndex`→`ColIndex`.
  Mechanical, gofmt-r-able, breaking; exactly what 0.5.0 is for.
- **Hide the sort plumbing**: `Len/Less/Swap` (+ Series' non-standard
  `Equal(i, j)`) are `sort.Interface` internals on public contracts. Remove
  from the interfaces; the concrete types keep them unexported or as-is.
- **`Take(params ...int)`** on both: a variadic (start, stop, step) with no
  documentation. Replace with `Slice(start, end int)` and `TakeIndices([]int)`
  — or at minimum document the variadic meaning. **decide** the shape, **do**
  the docs either way.

## `series.Series` findings

- **`IsSorted() enchanter.SeriesSortOrder`** returns a tri-state, not a bool.
  Rename to `SortOrder()`.
- **`GetNullMask() []bool` materializes** a bool slice from the bit-packed
  mask on every call — an O(n) allocation that looks like a cheap getter.
  Rename per above and document the cost; once `Data_`/`NullMask_` are hidden
  (the other 0.5.0 item), consider exposing the packed form read-only for the
  engines that want it (the 0.4.0 aggregation engine reads `NullMask_`
  directly today).
- **Mutation semantics are undocumented and non-obvious.** Methods take value
  receivers and return `Series`, but the backing slices are shared: `Set`,
  `SetNullMask`, `MakeNullable` mutate storage the caller may also hold.
  Write the ownership contract down per method (mutates in place vs returns a
  view vs copies); this is a 1.0 blocker more than an 0.5.0 code change.
- **`Not()` breaks the operator symmetry.** Every binary operator exists on
  every series type via codegen and returns `Errors` when unsupported; `Not()`
  exists only on `Bools` and `NAs`, so it cannot be called through the
  interface at all. Generate `Not()` for every type (Errors on unsupported)
  and add it to the interface next to `And`/`Or`.
- **`FilterIntSlice(mask []int, check bool)`** is a public micro-optimization
  (the bare `check` flag skips bounds validation). Unexport it or fold it into
  `Filter`'s documented contract.
- **`SeriesNumeric`** returns `any` from every statistic and takes
  `Quantile(q any)`. After 0.4.0 the aggregation engine computes these
  per-group without this interface; decide whether `SeriesNumeric` remains the
  per-series stats surface (then return `float64` and take `float64`) or is
  trimmed. **decide**.
- **`Data() any` contract**: view or copy? Today it is the backing slice (a
  view) for most types. Must be documented before the fields are hidden,
  because it becomes the only door.
- Comment nits fixed alongside this review: "Copie the series", and the
  `DataFrame` comments for `NameAt` (claimed "as a bool series") and
  `AddSeriesFromInts` (claimed "Int32s").

## `dataframe.DataFrame` findings

- **Column accessors are a grab-bag**: `C(name)`, `At(index)`,
  `NameAt(index)`, `GetSeriesIndex(name)`. Proposal: `Col(name)`,
  `ColAt(i)`, `NameAt(i)`, `ColIndex(name)` — keeping `C` as a documented
  shorthand alias if its brevity is loved (it is used everywhere in tests and
  downstream). **decide** whether `C` stays.
- **IO builders return unexported types** (`*csvReaderWrapper` …), and
  *reading* hangs off an existing frame: `NewBaseDataFrame(ctx).FromCsv()`.
  A reader does not need a receiver. Standardize (the roadmap already says so)
  on package-level reader constructors and receiver-based writers:
  `dataframe.ReadCsv(ctx).…` and `df.WriteCsv().…`, with exported builder
  types so callers can store and document them.
- **Join constants are SCREAMING_SNAKE** (`INNER_JOIN`): rename to
  `JoinInner`, `JoinLeft`, `JoinRight`, `JoinOuter`. While in there, make the
  row order of `Join` part of the contract — today it is map-iteration
  nondeterministic (issue #24); `GroupBy().Agg()` already sorts by key, so
  joins are the odd one out.
- **`AddSeriesFrom<Type>s` × 7**: `NewSeries` already dispatches on `any`, so
  `AddSeries(name, any)` could subsume them; the typed variants aid
  discoverability. Keep, but consider generating them (they are hand-written
  boilerplate today).
- **`Filter(mask any)`** is documented as "by a `Bools` series" but accepts
  more; align the doc with the actual accepted set.

## A behavioral finding to decide separately (not an interface item)

Operations with an `NAs` operand whose result is typed (e.g. `Bools.Or(NAs)`)
return a series marked **not nullable** that nevertheless carries a copy of
the typed operand's null mask. The 2026-09 generator flattening preserved
this verbatim (`naOperandNullMask`), because changing it is a semantic
decision: the sensible contract is probably "result of anything with NA is
NA" (which is what happens when the *result* type is NAs), or at least
`IsNullable_` consistent with the mask it carries. Worth its own issue.

## Suggested batching

| When | What |
|---|---|
| 0.5.0, mechanical | `Err() error`; Get-prefix drop; `SortOrder()`; hide sort plumbing; `Not()` everywhere; join constant rename; comment fixes |
| 0.5.0, with design | interface-vs-struct for DataFrame; reader-constructor standardization; `Take`→`Slice`/`TakeIndices`; `SeriesNumeric` shape |
| 1.0 gate | mutation/ownership contract written and tested; `Data()`/mask exposure decided together with hiding `Data_`/`NullMask_` |
